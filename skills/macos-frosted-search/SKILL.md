# 磨砂检索工作台

从一项真实查阅任务出发，先确定用户用哪些字段比较记录、在哪里核对原文、如何回到刚才的结果。读取[设计尺度](references/MACOS-UI-SCALE.md)，在已有页面结构和组件中落实相应的视觉与交互规则。

“搜索”“清除筛选”“返回结果”等操作词固定。业务实体、命中数量、引用原句和出处定位均从当前数据源读取；来源从 JSON 换成数据库时，保留先看摘要、再核对原文的阅读顺序。

1. **组织信息。** 左侧目录负责变更查询范围，标题旁给出当前命中数；横向筛选只作用于当前结果。表格优先显示便于比较的字段，选择一行后再打开阅读页。
2. **安排材质。** 把可透出静态底景的表面留给导航、工具栏和临时弹层。结果区使用接近实色的浅底，正文使用不透明底；先确保实色模式下各层和选中态仍清楚。
3. **核对名称。** 精简说明后，逐项检查输入框、图标按钮和筛选控件是否仍可识别。让用户能区分全库检索与当前结果内筛选。
4. **保留回路。** 记录打开前的查询、筛选、滚动和焦点。返回后恢复到同一条目；键盘、触摸和鼠标均能进入和退出阅读。

设计或评审时说明所采用的页面和控件。若可运行，实测窄屏、实色模式及一次完整的键盘查询与返回；若只有截图，明确把键盘和可访问名称列为待验证。用户仅要求精简文案时，把改动限于文案与必要的控件命名。

## 文案减法

> 删去标题和控件已经说清的说明，保留字段名、单位、状态、出错后的可行操作，并给每个交互控件独立命名。
